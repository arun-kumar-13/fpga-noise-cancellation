# Real-Time Audio Noise Cancellation on FPGA (Wiener Filter + MCRA)

Real-time speech noise suppressor running on the **Nios II soft-core processor** of an **Altera/Intel DE2-115** board (Cyclone IV E, EP4CE115F29C7).
Audio from a microphone is sampled by the on-board **WM8731** codec, cleaned in the frequency domain with a **Wiener filter** whose noise estimate is tracked by **MCRA** (Minima Controlled Recursive Averaging), and played back on headphones.

*Course project: Digital System Design using FPGA (MAVLD503), VIT Vellore, Fall 2026-27*

*Team: S. Prajwal (26MVD0017), R. Arun Kumar (26MVD0014), P. Hari Krishna (26MVD0002)*

## 1. How it works

```
 Mic ─► WM8731 ADC ─► Audio core FIFO ─► Nios II (C code) ─► Audio core FIFO ─► WM8731 DAC ─► Headphones
                                          │
          DC removal → 256-sample frame, 50 % overlap (hop 128) → √Hann window → 256-pt FFT
          → power spectrum → MCRA noise estimate → Wiener gain (decision-directed SNR, floor -16 dB)
          → optional noise gate → IFFT → √Hann window → overlap-add
```

| Parameter            | Value                                  |
|----------------------|----------------------------------------|
| Sample rate          | 8 kHz, 16-bit, mono (left channel)     |
| Frame / hop          | 256 / 128 samples (32 ms / 16 ms)      |
| FFT                  | 256-point radix-2 DIT, single-precision float |
| Noise estimator      | MCRA (≈1 s minimum-tracking window)    |
| Gain                 | Wiener, decision-directed a priori SNR (α = 0.98), floor 0.15 |
| Processing latency   | ≈ 32 ms (one hop + one primed output block) |
| Float maths          | Nios II **Floating Point Hardware 2** custom instructions |

All tunable constants are in [`software/app/params.h`](software/app/params.h).

## 3. Requirements

**Hardware**
- Terasic DE2-115 board + 12 V power adapter + USB cable (USB-Blaster port)
- Microphone → **pink** jack (MIC IN)
- Headphones or powered speaker → **green** jack (LINE OUT)

**Software** (versions used to build this project)
- Intel Quartus Prime **Lite 18.1** with Cyclone IV device support
- Nios II EDS 18.1 (Nios II Software Build Tools for Eclipse + Nios II Command Shell)
- Intel **University Program IP 18.1** (provides the Audio, Audio-and-Video-Config and Audio-Clock cores)
- USB-Blaster driver

## 4. Platform Designer (Qsys) system

If you are rebuilding the hardware, the system must contain these components. **Keep the component names exactly as shown**, because `main.c` uses the `*_BASE` macros that `system.h` derives from them.

| Component name             | IP core                                    | Settings |
|----------------------------|--------------------------------------------|----------|
| `clk_0`                    | Clock Source                               | 50 MHz (CLOCK_50) |
| `nios2_gen2_0`             | Nios II Processor (Gen2)                   | Nios II/f recommended |
| `nios_custom_instr_floating_point_2_0` | Floating Point Hardware 2      | connect to the CPU custom-instruction port |
| `onchip_memory2_0`         | On-Chip Memory (RAM)                       | 128 KB (program uses ≈ 86 KB) |
| `jtag_uart_0`              | JTAG UART                                  | stdout / stderr |
| `timer_0`                  | Interval Timer                             | system timer |
| `audio_pll_0`              | Audio Clock for DE-series Boards           | 12.288 MHz → AUD_XCK |
| `audio_and_video_config_0` | Audio and Video Config                     | DE2-115, **mic input**, 16-bit, **8 kHz**, left-justified/I²S |
| `audio_0`                  | Audio (UP core)                            | **Avalon-MM** (memory-mapped) interface, 16-bit, in + out |
| `switches`                 | PIO input, 18 bits                         | SW[17:0] |
| `keys`                     | PIO input, 4 bits                          | KEY[3:0] |
| `ledr`                     | PIO output, 18 bits                        | LEDR[17:0] |
| `ledg`                     | PIO output, 9 bits                         | LEDG[8:0] |

The codec sampling rate in `audio_and_video_config_0` must be **8 kHz** (the DSP assumes `FS_HZ = 8000`).

## 5. Build and run — step by step

### Step 1 — Clone
```bash
git clone https://github.com/arun-kumar-13/fpga-noise-cancellation.git
cd fpga-noise-cancellation
```

### Step 2 — Program the FPGA
1. Connect the DE2-115 USB-Blaster port to the PC and power the board on. Set **SW19 (RUN/PROG) to RUN**.
2. Open Quartus → **Tools ▸ Programmer**.
3. *Hardware Setup* → select **USB-Blaster**, mode **JTAG**.
4. *Add File* → `hardware/output_files/<top>.sof` → tick **Program/Configure** → **Start**.
   Progress must reach 100 % (Successful).

> **Rebuilding the hardware instead:** open `hardware/<top>.qpf`, open `<system>.qsys` in Platform Designer and click **Generate HDL**, then **Processing ▸ Start Compilation**, then program the new `.sof` as above.

### Step 3 — Open the Nios II Command Shell
Windows: *Start ▸ Intel FPGA 18.1 ▸ Nios II Command Shell*. All commands below run in this shell.

### Step 4 — Generate the BSP
```bash
cd software
nios2-bsp hal bsp ../hardware/<system>.sopcinfo
```
This creates `software/bsp/` with `system.h`, the HAL drivers and the linker script.
Check that `bsp/system.h` contains `AUDIO_0_BASE`, `SWITCHES_BASE`, `KEYS_BASE`, `LEDR_BASE` and `LEDG_BASE`.

### Step 5 — Build the application
```bash
cd app
make
```
The Makefile builds the BSP library and then `dsp_core.elf` (optimisation `-O2`). It also writes `dsp_core.map` and `dsp_core.objdump`.

> **Eclipse alternative:** *File ▸ New ▸ Nios II Application and BSP from Template* → pick the `.sopcinfo` → template **Blank Project** → copy the files from `software/app/` into the application project → *Build Project*. Use *Run As ▸ Nios II Hardware* to download it.

### Step 6 — Download and run
```bash
nios2-download -g dsp_core.elf
nios2-terminal
```
The terminal shows `Noise suppressor start`. Press **Ctrl+C** to close the terminal; the program keeps running on the board.

*(If you skip the build, you can run the pre-built `software/app/dsp_core.elf` directly, as long as the board is programmed with the matching `.sof`.)*

## 6. Using the board

| Control | Function |
|---------|----------|
| **SW0** | Noise reduction **on** (up) / bypass (down). Switching it on starts noise learning. |
| **SW1** | Noise gate on: noise-only frames are faded down by about 34 dB more |
| **SW2** | Replace the output with a 1 kHz test tone (checks the output path) |
| **KEY0** | Learn the noise again; keep the room quiet for about 1 s |
| **KEY1** | Clear the warning LEDs |

| LED | Meaning |
|-----|---------|
| LEDR0–17 | Input level meter, 3 dB per LED |
| LEDG0 | A block finished late (real-time deadline missed) |
| LEDG1 | Output FIFO ran empty (underrun) |
| LEDG2 | Learning the noise |
| LEDG3 | Noise reduction on |
| LEDG4 | Noise gate on |
| LEDG7 | Input clipping |

**Demo procedure**
1. All switches down. Speak into the mic: you hear yourself unchanged on the headphones, and LEDR moves.
2. SW2 up: a steady 1 kHz tone confirms the output path. SW2 back down.
3. With only background noise present (fan, AC, played-back noise), flip **SW0 up** and stay quiet while **LEDG2** is lit.
4. Speak: the background noise is strongly reduced and the speech stays clear. MCRA keeps adapting if the noise level changes.
5. Optionally flip **SW1 up** to silence the residual noise in pauses between words.
6. If the environment changes a lot, press **KEY0** in a quiet moment to learn the noise again.

## 7. Tuning (`software/app/params.h`)

| Constant | Default | Effect |
|----------|---------|--------|
| `G_MIN` | 0.15 | Gain floor. Lower = more suppression, but more "musical noise". |
| `A_DD` | 0.98 | Decision-directed smoothing. Higher = smoother, less musical noise, slower response. |
| `DELTA` | 5.0 | Speech-presence threshold for MCRA. |
| `MCRA_L` | 64 | Minimum-tracking window in frames (≈ 1 s). |
| `A_D` | 0.95 | Noise-update forgetting factor. |
| `INIT_FRAMES` | 8 | Frames averaged for the initial noise estimate. |
| `GATE_THRESH`, `GATE_FLOOR`, `GATE_HANG` | 2.0, 0.02, 6 | Noise-gate threshold, closed gain and hold time. |

After changing a value, run `make` and `nios2-download -g dsp_core.elf` again.
Keep the `f` suffix on every float constant: a double constant pulls in slow software double-precision maths on the Nios II.

## 8. Troubleshooting

| Symptom | Check |
|---------|-------|
| `nios2-download`: *no Nios II processors found* | The `.sof` is not loaded, or the board was power-cycled. Repeat Step 2. Check that SW19 is on RUN. |
| `make` error: *BSP directory does not exist* | Run Step 4 first. The BSP must sit in `software/bsp/`. |
| Compile error: `AUDIO_0_BASE` (or another `*_BASE`) undeclared | A component name in Qsys differs from Section 4. Rename it, regenerate, then regenerate the BSP. |
| No sound at all | Mic in the **pink** jack, headphones in the **green** jack. Use SW2 to test the output path. Check the codec config uses the mic input and 8 kHz. |
| LEDR meter does not move | Codec input path or mic boost not enabled in `audio_and_video_config_0`, or the mic is not plugged in. |
| LEDG0 / LEDG1 keep lighting | Processing is too slow. Check that Floating Point Hardware 2 is connected (`custom` instructions in `dsp_core.objdump`), that the build uses `-O2`, and that the CPU is Nios II/f. |
| LEDG7 lit / distorted sound | The input is too loud. Move the mic away or reduce the mic boost. |
| Speech sounds watery or muffled | Learn the noise again (KEY0) while it is quiet, or raise `G_MIN`. |
